2. Concept and separate worked example

A comparison produces a Boolean. A conditional uses that Boolean to choose which statements execute. Python checks an if condition first. If false, it checks the next elif condition. The first true branch runs; otherwise else runs. Colons introduce branches. Indent each branch body consistently, using four spaces. Only the selected branch body executes.

Separate example: a fictional container accepts integer counts from 0 through 4. The following example classifies a count; it is not the assigned exercise.

count = 2 if count < 0: print(“Negative count”) elif count > 4: print(“Too many”) else: print(“Within stated range”)

With count=2, both tests are false, so else runs. With count=-1, the first branch runs. With count=5, the second runs. At 0 and 4, else runs because the bounds are inclusive. Two separate if statements are not the same as one mutually exclusive if/elif/else chain.

A calculation placed after the whole chain runs regardless of which branch ran. To restrict a model calculation, place it inside the accepted branch. Assign outputs afresh on each run or keep them local to a function so an old result cannot be mistaken for a new one.

3. Assigned practice: a guarded ground-test model

Supplied fictional model: distance d=9*t metres for a cart at constant 9 m/s, valid only for elapsed time from 0 through 10 s inclusive. Acceleration and wind are omitted. Bounds are teaching assumptions, not a safety certification. Inputs today are real numerical values already expressed in seconds; text/type validation is outside scope.

  1. In Markdown, predict which branch should run for times -1, 0, 4, 10 and 11 s. Name the two rejected regions and the accepted region.
  2. Write an if/elif/else chain that prints a distinct message for negative elapsed time, time above the model limit, or an accepted time. In the accepted branch only, calculate distance and print it with units. Do not clamp invalid times to an endpoint or report zero distance for them.
  3. Run the same cell separately with each supplied input, recording input, predicted branch, actual message and any reported distance in a Markdown table. No loop is needed.
  4. Put the decision inside a function report_distance(time_s). Use print in each branch; do not require a return value. Call it explicitly for the five inputs. Compare with the single-input version.
  5. Explain what would go wrong if the distance calculation and print were moved below the entire chain without indentation. Explain why printing a rejection does not itself stop later statements from running.
  6. Change an endpoint comparison deliberately so equality at 10 s is rejected. Predict and observe which test changes, then restore the required inclusive rule.

4. Checks, interpretation and stretch

Success checks: exercise all three branches; check both endpoints separately; invalid inputs produce no model distance; accepted distances agree with direct substitution; each function call prints exactly one classification. Run an accepted input followed by a rejected input to look for stale output. Restart the kernel and run your completed notebook top-to-bottom.

Explain in two sentences how a Boolean differs from the branch it controls. State what your guards enforce and what they cannot establish about the physical accuracy of the supplied model.

Optional stretch: change the upper limit to 6 s. Predict which of the original input classifications change and verify with explicit calls.

Remediation: if the wrong branch runs, evaluate each comparison separately as in Lesson 021. If every input gets a distance, inspect indentation. If an endpoint fails, revisit < versus <=. Record comfortable / needs practice for comparisons, branch order, indentation and model guards.
