Lesson 020: Input domains and physical constraints

Objective: Distinguish inputs that an expression can evaluate from inputs allowed by a supplied physical model. Prerequisites: Lessons 005-019, arithmetic, units, functions and tables. Time: 15-30 minutes, plus optional reading. Python 3 only.

2. Concept and worked example

A domain is a set of allowed inputs. An expression may produce a number even when the input has no meaning for its model. Physical assumptions can restrict inputs more than arithmetic does.

Separate example: a fictional cart has position p(t)=3+2*t metres for elapsed time from 0 through 4 seconds, including both endpoints. The expression evaluates at t=-1 and t=5, but those times are outside the supplied model interval. At t=2 it gives 7 m. A finite table only samples the interval; it does not list every allowed input.

For an average speed d/t, zero elapsed time is excluded by division; negative elapsed time is excluded by this elapsed-time interpretation. State constraints in words today. Comparisons and conditionals will be taught next.

3. Assigned practice

Supplied educational model: a fictional ground-test vehicle travels at 8 m/s for elapsed times from 0 through 6 s, including endpoints. Distance traveled is d(t)=8*t metres. Acceleration and wind are omitted.

  1. Write the input, output, units and allowed time interval in words.
  2. Classify each time -2, 0, 1.5, 6 and 9 s as inside or outside the model domain in a Markdown table. Give a reason before computing.
  3. Define distance_m(time_s). Evaluate all five times explicitly, keeping outside-domain evaluations clearly labeled as arithmetic only. Explain why a returned number does not authorize extrapolation.
  4. A supplied diagnostic computes speed as distance/elapsed_time. Evaluate it using the model distance at 1.5 and 6 s. Explain why using t=0 would divide by zero; do not execute that division.
  5. Extend the table with 3 s, an interior point not in the original sample. Explain whether a missing table entry is an excluded input. No loops or branching are required.

4. Checks and reflection

Check both endpoints against the stated interval. Hand-substitute one interior input and compare with your function. Verify units (m/s)*s=m. Confirm that nonzero-time distance/time agrees with the supplied speed. Restart and run completed cells top-to-bottom.

Explain the difference between arithmetic evaluability, physical admissibility and evidence from measurements. These fictional inputs do not validate a vehicle.

Optional stretch: change only the stated end time to 4 s. Which classifications change while the expression stays the same? Explain without adding conditionals.

Remediation: revisit Lesson 010 for functions, 006 for units and 018 for the constant-speed assumption. Record comfortable or needs practice for endpoints, excluded inputs and extrapolation.
